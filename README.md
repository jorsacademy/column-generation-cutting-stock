# Column Generation Cutting Stock

A reproducible Operations Research implementation of **column generation** for the one-dimensional cutting-stock problem. The project exposes the restricted master problem, demand dual prices, knapsack pricing problem, reduced costs, stopping rule, and the important distinction between solving the LP relaxation and proving integer optimality.

## Problem

A stock roll has length `L`. Item type `i` has length `l_i` and demand `d_i`. A cutting pattern `p` is a nonnegative integer vector `a_ip` satisfying

```text
sum_i l_i a_ip <= L.
```

If `x_p` is the number of rolls cut with pattern `p`, the classical integer master problem is

```text
minimize    sum_p x_p

subject to  sum_p a_ip x_p >= d_i      for every item i
            x_p integer and nonnegative.
```

The difficulty is that the number of feasible patterns can be very large. Column generation avoids listing them all when solving the LP relaxation.

## Restricted master problem

The algorithm starts with a small feasible pattern set, here one maximal single-item pattern for each demanded item type. It solves

```text
minimize    sum_p x_p

subject to  sum_p a_ip x_p >= d_i
            x_p >= 0
```

over only the current columns.

The LP returns demand dual prices `pi_i`. A high dual price means one additional unit of that demand is expensive in the current restricted master.

## Pricing problem

A new cutting pattern has reduced cost

```text
1 - sum_i pi_i a_i.
```

Therefore pricing is an unbounded integer knapsack problem:

```text
maximize    sum_i pi_i a_i

subject to  sum_i l_i a_i <= L
            a_i integer and nonnegative.
```

If the optimal pricing value is greater than `1`, the corresponding column has negative reduced cost and can improve the master LP. The implementation solves pricing by dynamic programming, not by enumerating all patterns.

The loop stops when

```text
1 - best_pricing_value >= -tolerance.
```

At that point, no negative-reduced-cost pattern exists and the restricted master objective equals the full pattern LP optimum, up to numerical tolerance.

## Gilmore-Gomory structure

This is the classical cutting-stock decomposition associated with Gilmore and Gomory. Their 1961 paper addressed the impractical number of variables in the direct LP formulation by generating useful columns instead of keeping the full pattern matrix explicitly.

The implementation follows the same structural idea while using modern open-source numerical solvers for the master problems.

## Integer solutions: an important limitation

Plain column generation solves the **LP relaxation**. It does not by itself solve the integer cutting-stock problem.

A common practical step is to solve an integer restricted master over the columns generated by the LP algorithm. This repository reports that solution, but labels it correctly: it is an integer solution over the generated column pool, not a general proof of global integer optimality.

The tests include a counterexample:

```text
stock length = 8
item lengths = (2, 3, 4)
demands      = (1, 3, 1)

column-generation LP optimum      = 2
restricted integer master         = 3
full enumerated integer optimum   = 2
```

The LP pricing loop has converged, yet a pattern needed for the best integer solution never had negative LP reduced cost. Exact large-scale integer column-generation methods therefore require machinery such as **branch-and-price** rather than simply rounding or integerizing the final restricted master.

## Small-instance verification

For the synthetic demo, every feasible pattern is also enumerated after column generation. This is deliberately used only as a benchmark. The automated checks compare

- the column-generation LP optimum with the full enumerated LP optimum,
- the restricted integer master with the full enumerated integer master,
- the final dual prices with a fresh pricing solve.

The default instance is

```text
stock length:  110
item lengths:  (20, 45, 50, 55)
demands:       (48, 35, 24, 10)
```

With the deterministic implementation, column generation starts from four single-item patterns, generates two mixed patterns, and converges to an LP objective of approximately `39.583333`. The restricted integer master and full enumerated integer model both use `40` rolls on this instance.

These values are verification results for this small synthetic instance, not claims about computational performance on industrial cutting-stock benchmarks.

## Installation

```bash
python -m pip install -e ".[dev]"
```

Python 3.10+ is supported.

## Run

```bash
python -m cutting_stock
```

or

```bash
python examples/run_demo.py
```

The JSON output reports the LP objective, number of generated columns, final reduced cost, full-pattern LP verification, restricted and full integer objectives, selected patterns, and the full column-generation iteration trace.

## Tests

```bash
python -m pytest
```

The suite verifies pattern feasibility and enumeration, dynamic-programming pricing against brute-force pattern enumeration, monotone restricted-master improvement, LP convergence, absence of negative reduced-cost columns at termination, agreement with the full LP, integer-master behavior, the integer-optimality counterexample, and CLI output.

GitHub Actions runs package installation, bytecode compilation, and the complete test suite on Python 3.10 and 3.12.

## Methodological notes

- Column generation is a decomposition algorithm for large-variable LPs; it is not itself a metaheuristic.
- Dual values come from the restricted master and define the pricing objective.
- Negative reduced cost is the criterion for adding a column in this minimization model.
- The pricing subproblem is an unbounded integer knapsack because a pattern may contain multiple copies of an item type.
- Full pattern enumeration appears only in tests and verification utilities. It is not used by the column-generation loop.
- A restricted integer master can be useful operationally, but equality with the true integer optimum must not be assumed.
- Branch-and-price is the natural exact extension when integer optimality is required without explicit enumeration of all columns.
